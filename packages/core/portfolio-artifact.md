# Portable Portfolio Artifact v1

Core exports a portable directory artifact from a validated Semantic Graph v1. The manifest records the unchanged Scene v1 and semantic contract versions, a stable subject identity and fingerprint, and SHA-256 digests and UTF-8 byte lengths for every asset. The directory contains the canonical graph, projected `scene.json`, accessible static SVG fallback, standalone interactive HTML, Semantic Markdown, and `manifest.json`. The HTML uses the existing renderer/runtime and embeds its runtime, so deployment requires no Studio, GitHub access, remote code, or separate WASM file.

```js
import { createPortfolioArtifact, validatePortfolioArtifact } from '@constellation/core';

const artifact = await createPortfolioArtifact(semanticGraph);
await validatePortfolioArtifact(artifact.files['manifest.json'], artifact.files);
```

Creation and validation use Web Crypto SHA-256. Validation bounds the manifest to 16 KiB, each file to 16 MiB, the bundle to 32 MiB, and the asset count to 12. It validates Scene v1 and Semantic Graph v1, checks their subject and fingerprint agree with the manifest, checks Scene project identities exist in the graph, and rejects unsupported versions, missing or mismatched digests, unsafe paths, unexpected executable filenames, and incorrect entry points. `constellation.html` is the only executable artifact and is generated by Core from the validated Scene. Consumers must obtain the manifest and files from a trusted distribution channel; hashes detect corruption and mismatch, not a maliciously replaced manifest.

The artifact preserves source-backed identities and evidence through the semantic graph and embeds a matching scene for direct component loading. It contains no credentials, session state, or user-authored executable configuration. Static `constellation.svg` remains usable when JavaScript or WebAssembly is unavailable. The standalone HTML entry embeds the generated runtime and WASM; validation checks its offline runtime marker and CSP in addition to validating the Scene, paths, sizes, and digests. Web Component integrations may load `scene.json` with `src`, or set the validated scene property directly; the standalone HTML needs no network after it is downloaded.

Create the directory form offline with `constellation --semantic-graph input.json --format portfolio --output ./dist/portfolio`. Studio's existing Portfolio website destination downloads a single JSON container with the same manifest and named files; unpack the files before static hosting. Studio reports setup only and does not verify deployment. The CLI directory form is the preferred package-manager workflow for deployment automation.

Local Node.js 22.12.0 diagnostics: 12 projects created in 39.7 ms and validated in 3.0 ms (1,169,743 asset bytes); 100 projects created in 56.4 ms and validated in 3.8 ms (1,434,090 asset bytes). A 45-node standalone HTML bundle measured 1,196,237 total bytes with the existing 1,040,342-byte runtime and 670,680-byte WASM. These are local single-run timings, not device or network guarantees.

The isolated headless Chromium consumer fixture measured 304.8 ms from package import to first readiness, 0.9 ms for project and relationship focus, 20.0 ms for a 280px container resize and layout, and 2.9 ms for disconnect/reconnect. It uses local package copies and localhost; no live GitHub requests are needed.

Framework examples use the existing package and element. Plain HTML uses the published import map from [the Web Component guide](web-component.md). React should register the element once at module scope, assign `scene` in an effect, attach native `scene-ready`, `focus-change`, and `error` listeners, and remove those listeners on cleanup. Astro can import the same entry from a client-only script and use the element in markup. These are integration patterns, not separate renderers or framework packages.
